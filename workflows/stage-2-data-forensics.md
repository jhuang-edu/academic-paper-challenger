# Stage 2（Pass 2）：一手来源全量核验 + 全链路数据统计法医挑战工作流（Primary-Source Verification & Data Forensics）

本工作流融合了**“第二轮一手来源逐条复核（Primary-Source Second Pass）”**与**“全量数据交叉复算 + 统计法医挑战（Statistical Data Forensics）”**。站在最挑剔的审稿人与数据审计员视角，既对首轮问题及全文每个数字、法条、引文、案例回一手来源验证，又对实验台账（`.csv` / `.tsv` / `.xlsx`）发起合成痕迹与统计稳健性挑战。

---

## 1. 第一部分：一手来源全量复核（Primary-Source Second Pass）

1. **核心铁律——只引用亲自打开看过的一手来源（Cite Only Sources You Opened）**：
   - 搜索引擎的结果摘要（Search Snippet）、百科词条或二手转述/公众号转载**绝不是一手来源**；
   - **法条与规章**：必须核对人大/国务院/部委官方公布文本（核查条号与正文主张是否完全对应、施行日期与废止日期是否准确）；
   - **学术引文**：必须核对出版商官网、DOI 记录、知网/WoS/IEEE/ACM 原始索引记录（核查作者、年份、卷期页码，以及原文真实研究对象与结论是否被张冠李戴）；
   - **案例与标准**：核对法院裁判文书/监管机构公告及国家标准/ISO 标准原文；
   - **引文逐字核对**：直接引号引述的内容须逐字核对，若漏掉原文的**例外条款、适用前提或限定条件**，单独列为一条发现。
2. **四大刚性核验结论（Four Strict Verdicts）**：
   对首轮（First Pass）每一条及文中关键事实主张，在第二轮核验表中给出且仅给出以下四个结论之一（保持首轮清单不动，便于逐行对照）：
   - **`Confirmed`（属实）**：一手来源与核查结论/核实后的事实完全一致；
   - **`Discrepancy`（有出入）**：数字、日期、作者归属、条号或措辞与一手来源存在偏差；
   - **`Unverifiable`（无法验证）**：穷尽检索仍无法找到一手来源（记为带日期的待核实发现，注明已尝试检索的数据库，**绝不将无法验证的数字写成已证实**）；
   - **`Serious Error`（严重错误）**：论文表述的内容与一手来源直接相反或张冠李戴。

## 2. 第二部分：全量数据校验与统计法医挑战（Automated Data Forensics）

> **纯理论 / 纯质性论文豁免分支（N/A）**：若论文不含定量实验台账与统计汇总表，完成上述“第一部分：一手来源全量复核”及文内数字核对后，在 Stage 2 数据法医栏注明 `N/A 豁免` 即可进入 Stage 3。实证类论文严禁使用此豁免。

### 2.1 自动化复算与法医脚本（可重跑留档）

所有重算必须通过可重复运行的脚本执行（脚本与轮次日志一并留存，后续轮次直接重跑脚本，不手算第二遍）：

```bash
# 1. 台账全量描述统计、双口径 IQR、共线性、游程、末位数字、Benford 与混淆矩阵法医扫描
python scripts/data_forensics.py \
  --input <ledger.csv|tsv|xlsx> \
  [--sheet <sheet_name>] \
  [--id-col <id_column>] \
  [--group-col <group_column>] \
  [--num-cols <col1,col2,...>] \
  [--ref-col <truth_col> --pred-col <pred_col>] \
  --corr-threshold 0.90 --alpha 0.05 --format json

# 2. 正文二维表算术加总与自定义跨表公式断言核查
python scripts/cross_table_reconciler.py --docs <manuscript_docs...> [--rules <reconcile.json>] --tol 0.05 --format json
```

### 2.2 三层数据挑战与合伦理破局

1. **第一层：复算精度、取整掩盖与分母守恒挑战**
   - **先证伪再接受（Try to Disprove Before Accepting）**：从组成部分重算每一个总数与均值，检查总数是否被误写为只属于某个子集，检查取整是否掩盖了实质差距；
   - **双口径四分位距核验**：比对 `q1_inc / q3_inc / iqr_inc`（`PERCENTILE.INC`）与 `q1_exc / q3_exc / iqr_exc`（`PERCENTILE.EXC`），在表注或方法节显式声明分位数插值口径；
   - **分类与配对检验复算**：复核混淆矩阵 `TP/FP/TN/FN`、灵敏度/特异度/PPV/NPV、Cohen's $\kappa$ 与 McNemar 检验（当不一致格 $b+c < 25$ 时必须采用精确二项分布检验 $p_{\text{exact}}$）。
2. **第二层：7 大统计法医红旗挑战（识别“人工合成数据”嫌疑）**
   - **红旗 1：跨列线性乘数合成痕迹（$|r| \ge 0.90$）**——检查两组独立耗时或得分是否呈 $t_2 \approx \text{round}(k \cdot t_1, 1)$ 的近乎笔直线条；
   - **红旗 2：0/1 序列奇偶机械交替（Wald-Wolfowitz 游程检验 $p < 0.05$）**——检查标签列是否出现 `1, 0, 1, 0, 1, 0` 的手工配平负自相关游程，以及样本 ID 是否按类别整块排列而未做随机盲号打乱；
   - **红旗 3：样本阳性率与总体台账严重倒挂**——检查实验抽样样本的合格率/阳性率是否成倍高于历史总体台账而缺乏显式的分层抽样框配额公式；
   - **红旗 4：McNemar 配对中的“陪绑犯错”与真值独立性污染**——检查实验组升级/求助样本是否交由作为真值基准（Ground Truth）的同一专家裁决，导致测试与基准物理隔离失效；
   - **红旗 5：小样本子组“完美对称混淆矩阵”（如 `2/2/2/2 → 4/0/0/4`）与颗粒度跳变**；
   - **红旗 6：末位数字均匀性偏态（$\chi^2$ 检验）与窄区间滥用 Benford 定律**；
   - **红旗 7：组织工时、云厂商专有实例保底成本与财务 ROI 倒挂悖论**。
3. **第三层：合伦理破局决策**
   - 发现算术错误或跨期量纲笔误 $\to$ 立即平账并注明折算口径；
   - 属真实测量机制引发的表观规律（如共同阅读复杂度基线、按岗位归档后的分析编号、分层目的抽样配额） $\to$ 在方法论章节显式补齐抽样框配额公式、归档序 vs 随机施测序说明、共同基线效应及稳健性指标（中位数/IQR、去极值均值、子组观察边界声明）。

## 3. 输出产物与退出门禁

- 生成 Stage 2（Second Pass）一手来源核验对照表（每项标注 `Confirmed / Discrepancy / Unverifiable / Serious Error` 及亲自打开核实的一手来源出处）与统计法医挑战报告；
- **退出门禁**：所有文内数字与表格算术全平（容差 `<= 0.05` 或已注记四舍五入）、一手来源核验无未处置的 `Serious Error / Discrepancy`、统计法医红旗全部完成归因与方法论破局。
